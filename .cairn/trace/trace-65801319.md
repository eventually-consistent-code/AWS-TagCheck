# Trace: Phase 2 verify REFUTED: age-out projector omits Glacier per-object overhead (sign-flipped recommendation on tiny-object cells); plus unsupported INT→Standard-IA transition modeled, missing marginal_rate and CLI target override, delete option blind to non-transition-class stale data, refresh region mislabeling

## evidence — 2026-07-31
Adversarial verifier repro: 1M × 1 KiB objects in >365d band — age-out reports +$0.02/mo (recommends), archive reports −$0.18/mo (not_recommended), true age-out→GLACIER math with 8/32 KiB overhead is −$0.27/mo. Same data, same destination, opposite verdicts. Also confirmed: INT→STANDARD_IA not in AWS's supported lifecycle transitions; no marginal_rate anywhere (savings overstated +3.7% at 61 TB, ~9.5% at 500 TB); stale GLACIER cells produce delete=$0.00 "NOT RECOMMENDED" (should be real savings); pricing_refresh restamps region/date but keeps us-east-1 fee data. Math primitives (tier ladder, floors, INT exclusion, GB/GiB) all survived hand recomputation.

## hypothesis — 2026-07-31
Root causes, one per finding: (1) age-out reused billable-floor math but never the archive overhead helper — overhead applies to ANY transition into Glacier classes, not just the "archive" option; (2) TRANSITION_SOURCE_CLASSES treats INT like STANDARD for every target, but AWS only allows INT→(OZ-IA/GIR/Glacier/DA); (3-4) marginal_rate and the CLI override were planned but never implemented — plan text, no code; (5) _stale_cells filters delete's input by transition-eligibility, conflating "can't transition" with "can't delete"; (6) refresh updates only storage ladders yet restamps the whole snapshot's region. Fix set: shared overhead in age-out, INT target restriction, marginal-rate savings basis per class, --age-out-map CLI flag keyed on day values, delete over ALL stale classes, refresh region warning, plus nits (schema guard before scan, empty-slice messaging, <128 KiB transition-exclusion caveat).
